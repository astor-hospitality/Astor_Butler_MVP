# Astor: переговоры консьержа и батлера — дизайн

Дата: 14.10.2026. Одобрено Михаилом в диалоге 14.10 (части 1–3, «всё ок, уходим в реализацию»).
Зависит от: #202 (лента визита `guest_visits`, этапы, оси диплома), #200 (живая форма брони Saby).

## 1. Что такое продукт

Astor — система гостевого внимания. Две роли ИИ, два голоса в одном чате гостя:

- **Консьерж — агент гостя.** Ведёт разговор, ищет место в городе, отстаивает цели гостя (быстро, вкусно,
  в бюджет, без лишних сообщений). Живёт в Astor_Concierge (Node, Telegram), говорит своим голосом.
- **Батлер — агент ресторана.** Работает на цели заведения (заполнить зал, продать ланч, держать оборот стола,
  получить отзыв и возврат). Владеет обязательствами: бронь, заказ, счёт, Saby, персонал. Живёт в Astor_Butler_MVP
  (Java). В чате Консьержа говорит сам с подписью «AERIS · Батлер»; в своём боте (QR на столе) — напрямую.
- **Персонал** — третья сторона: хостес, официант, менеджер, очки. Видит карточки и жмёт кнопки, как сейчас.

Гость, начавший у Консьержа, остаётся в его чате до отзыва. Перехода в другой бот нет.

## 2. ИИ и FSM

- Состояние **разговора** ведёт LLM (GigaChat) с вызовом инструментов, у каждого агента свой системный промпт
  с явными целями своей стороны.
- Состояние **обязательств** — строгие машины состояний доменных сервисов Батлера. ИИ может попросить
  «создай заявку», но переход «ждёт хостес → подтверждена» делает только хостес или Presto. Деньги и обещания
  ресторана от решения модели не зависят.
- Сценарии FSM остаются: (1) эталонные диалоги для тестов и оценки агентов; (2) источник примеров интентов,
  фактов и RAG; (3) запасной путь, когда GigaChat недоступен (402, нет ключа, таймаут) — прямой бот Батлера
  продолжает работать на сценариях.

## 3. Каталог инструментов — Capability API v1 (Батлер)

Один контракт, два потребителя: агент Консьержа по REST (`POST /api/capabilities/v1/{tool}`, токен внутри
docker-сети), агент Батлера изнутри через function calling. Схемы: `GET /api/capabilities/v1/tools`.

| Инструмент | Основа в коде | Защита |
| --- | --- | --- |
| `venue_info` | `venue/aeris.json` (#202) | чтение |
| `lunch_menu` (цены, вес, КБЖУ) | `BusinessLunchCatalog`, `SabyNutritionService` | чтение |
| `table_availability` | `TableReservationService.availability` | чтение |
| `reservation_create` | `createReservation` | обязательство: только «ждёт хостес» |
| `reservation_change`, `reservation_cancel` | `changeByGuest`, `cancelByGuest` | обязательство |
| `lunch_order_place` | `BusinessLunchService.place` | обязательство: только после явного «да» гостя на показанный итог |
| `table_request` | `TableRequestRouter` (#202) | только этап SEATED |
| `bill_request` | обёртка над `GuestBillRequestService` | ссылку даёт Saby, сумму ИИ не придумывает |
| `review_submit` | обёртка над `VisitReviewService` | один раз за визит |
| `tip_create` | `TipService.createDraft` | черновик, подтверждает гость |
| `visit_status` | `guest_visits` (#202) | чтение |

Правила: инструмент возвращает факт, а не текст для гостя; каждый вызов пишется в ленту; обязательства
идемпотентны по ключу вызова (повтор после таймаута не создаёт вторую бронь или заказ).

Шлюз моделей: `ModelCapability.TOOL_CALLING`, `functions` в `GigaChatModelGateway`, цикл агента
«модель → инструмент → результат → модель», не больше 5 шагов за реплику.

**Переговоры агент ↔ агент:** `POST /api/negotiation/v1/turn` — Консьерж передаёт Батлеру реплику гостя
и свою позицию (цели гостя); Батлер отвечает репликой для гостя (своим голосом), предложением
(`offer`: время, стол, ланч, условия) и фактами инструментов. Консьерж решает, принять, спросить гостя
или торговаться дальше.

**Батлер → Консьерж:** подписанный вебхук на события (подтверждена, отклонена, утро, гость сел, счёт готов,
официант идёт) вместо опроса раз в минуту. Консьерж доставляет их в чат гостя голосом Батлера.

## 4. Лента визита

Таблица `visit_turns` (Батлер, Postgres): `visit_id` (или `session_id` Консьержа до выбора места; при открытии
визита сессия подвязывается), `at`, `side` (GUEST, CONCIERGE, BUTLER, STAFF, SYSTEM), `channel`
(CONCIERGE_TG, BUTLER_TG, STAFF_GROUP, GLASSES, SABY), `kind` (MESSAGE, TOOL_CALL, TOOL_RESULT, OFFER,
STAFF_ACTION, FALLBACK), `text` (телефоны маскируются), `payload` (JSON), `goal` (GUEST / VENUE / null).

Пишут: Консьерж — свои реплики и реплики гостя через `POST /api/ledger/v1/turns` (только с согласия гостя;
без согласия — без текста); Батлер — сам (агент, инструменты, кнопки персонала, Saby).
Лента пишется в своей транзакции и никогда не ломает бронь (урок C1 из #202).

## 5. Саммари визита

После визита (этап AFTER) и по кнопке на табло GigaChat собирает из ленты саммари, таблица `visit_summaries`:

- что хотел гость; что предложил ресторан; чем кончилось (бронь, ланч, сумма, отзыв);
- где застряли (повторы, непонятые реплики, уходы на FSM, ожидание хостес);
- **что поменять в следующий раз**: для этого гостя (память: «любит у окна, без лука, торопится») и для агентов
  (урок: «на вопрос о вине отвечать картой, а не ‘уточню’»).

Использование: память гостя подаётся агентам в следующем визите этого гостя (только с согласия);
уроки менеджер на табло принимает, правит или отклоняет — принятые попадают в инструкции агентов.
Ручная правка разговора: менеджер может дописать «в следующий раз» на карточке.

## 6. Табло — astor-ai.ru/board, вход по логину

- **Канбан**: колонки — этапы визита (заявка → подтверждена → день визита → за столом → счёт → после → вернулся;
  отдельно отмена и неявка). Карточка — визит: гость (маска), время, стол, сумма, сообщения гостя, отметка саммари.
- **Карточка открытая**: три дорожки во времени — *Гость* | *Консьерж ⇄ Батлер (переговоры, инструменты)* |
  *Персонал (карточки, кнопки, очки, Saby)*; саммари и «в следующий раз» сверху.
- **Метрики**: сообщения гостя за визит (цель ~40), доля переговоров, закончившихся бронью/заказом, время до
  подтверждения, конверсия в ланч, отзывы и возвраты, задержка и ошибки GigaChat, уходы на FSM, ошибки Saby.
- **Архитектура**: живая схема компонентов (Консьерж, Батлер, GigaChat, Saby, Postgres, Kafka, Redis, очки)
  с состоянием зелёный/жёлтый/красный.
- API Батлера: `/api/board/v1/visits`, `/visits/{id}/turns`, `/visits/{id}/summary`, `/metrics`, `/health-map`;
  обновления — SSE. Телефоны маскируются всегда; тексты — только после входа.

## 7. Очерёдность

| # | Часть | Риск для живого теста |
| --- | --- | --- |
| 0 | Ссылка Консьержа на `@aeris_butler_bot` | нет |
| 1 | Лента + табло на чтение + саммари, на текущих потоках | нет: гостю ничего не меняется |
| 2 | Function calling в шлюзе + Capability API v1 | нет: новые эндпоинты, за флагом |
| 3 | Агент Батлера + API переговоров | да: меняет ответы гостю — только для списка тестовых чатов |
| 4 | Агент Консьержа с инструментами, два голоса, вебхук | да: только для списка тестовых чатов |
| 5 | Цели, уроки, метрики по итогам | — |

Агентный путь включается флагом и списком chat id (`ASTOR_AGENT_ALLOWLIST`); остальные гости идут прежним путём.
