# PR #49 — безопасное изменение брони Saby

Дата: 2026-10-07.

- Найдено: payload для создания использовался как полный payload обновления. Он выставлял `woTable=true` и не содержал поля, добавленные рестораном (стол, блюда и данные гостя).
- Исправлено: перед PUT читается текущий заказ. Меняются время, число гостей, имя, телефон и добавляется описание изменения; остальные поля сохраняются.
- Если ответ неполный, принадлежит другой точке продаж или чтение завершается ошибкой, PUT не отправляется. Заявка остаётся для проверки хостес.
- Выбранный в Butler стол не считается идентификатором Saby. Стол Presto сохраняется; уведомление прямо просит хостес сверить посадку.
- PUT не повторяется после неопределённого результата.
- Ограничение: GET + PUT не являются атомарным обновлением. Одновременное редактирование рестораном требует проверки поддержки версии/ETag в реальном API.
- Проверка реального Saby не выполнялась: необходимы тестовые ключи и проверка формы ответа GET на тестовом заказе. Неизвестная форма ответа блокирует запись, а не стирает данные.
- Старое падение CI #37515894218 связано с `GlassesControllerTest`: ожидалось 409, получено 429. Это не падение теста Saby.
- Мерж и production-деплой этим исправлением не выполняются.
