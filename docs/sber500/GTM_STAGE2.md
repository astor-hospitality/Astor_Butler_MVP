# Концепция вывода на рынок: этап 2

Astor — система гостевого внимания для ресторанов. Две роли ИИ: **Astor Concierge** — агент гостя в Telegram, ищет место
и договаривается с заведением; **Astor Butler** — агент ресторана, ведёт бронь, бизнес-ланч, счёт, отзыв и карточки
персоналу. Пилот — гастробар AERIS, Екатеринбург. Цели в таблицах — **[заполнить]** после теста 15.10.

## 1. Сегмент и ICP

- **Сегмент:** рестораны и гастробары Екатеринбурга с бизнес-ланчем; потом города-миллионники.
- **ICP ресторана:** 60–150 посадочных мест; бизнес-ланч в будни; брони идут через телефон и мессенджеры и
  подтверждаются хостес вручную; касса Saby Presto (у нас есть интеграция) или другая с API; управляющий готов
  дать группу персонала в Telegram.
- **ICP гостя:** офисный сотрудник рядом с рестораном, обедает 2–5 раз в неделю, ценит время; гость вечера,
  который бронирует в Telegram.
- **Кто покупает:** собственник или управляющий; кто пользуется каждый день — хостес, официанты, менеджер смены.

## 2. Ценность

| Для ресторана | Для гостя |
| --- | --- |
| Заявки на стол и ланч приходят карточкой с кнопками «Да / Нет», а не звонком | Бронь и ланч в одном чате, без звонка |
| Ланч готовится ко времени прихода (пометка кухне «ПРЕДЗАКАЗ») | Еда ждёт, обед укладывается в перерыв |
| Отзыв и чаевые официанту — сразу после счёта | Счёт и оплата в боте, без ожидания официанта |
| Лента визита и табло: где гость застрял, что изменить | Узнавание при возврате: «как в прошлый раз» без повторного ввода |
| Подтверждение остаётся за хостес и кассой: ИИ не обещает от имени ресторана | Консьерж отстаивает интересы гостя: время, бюджет, без лишних сообщений |

Источник ценностей для ресторана — 6 интервью персонала AERIS (10–12.10) и опрос управляющего № 7.

| Гостевые мероприятия | ужины и дегустации в пилотном ресторане, запись только через бота | лояльные гости, сарафан |

## 5. Маркетинговые подходы

- **Кейс AERIS** как главный аргумент: реальные числа ленты визита (визиты, время до подтверждения, отзывы) на одной странице.
- **Вход через операционную боль**, а не через ИИ: «хостес не теряет заявки», «ланч готов ко времени».
- **Пилот на 4 недели** с порогом успеха, согласованным с управляющим заранее.
- **Сервис без смены привычек персонала:** всё в Telegram-группе, которая у ресторана уже есть.
- **Еженедельный отчёт** управляющему по вторникам — удержание клиента через видимый результат.

## 7. Риски

| Риск | Что делаем |
| --- | --- |
| Мало живых гостей в пилоте (на 14.10: 16 гостей, 4 заявки, 0 подтверждённых) | QR на столах, канал AERIS, мероприятия; считаем каждый шаг воронки |
| Хостес не жмёт «Да» в пиковую смену | автоподтверждение по таймеру (#159), передача менеджеру |
| Saby Presto в живом режиме ещё не вызывался | read-only smoke до записи, работа без Saby в полуавтомате |
| Стоимость агентного режима | бюджет промпта, выбор 3-Pro по замеру, агенты только по списку чатов |
| Ошибка ИИ в обещании гостю | обязательства только через FSM и человека; ИИ не подтверждает бронь и сумму |
| Согласие на хранение диалога | спрашиваем явно; без согласия — лента без текста |
| Зависимость от одного ресторана | второй ресторан через Saby на этапе 2: [заполнить] |
