## 2. Целевой сценарий

**Гость → заявка на стол или бизнес-ланч → подтверждение хостес → визит.**

1. Гость пишет боту (`/start`, deep-link с сайта, QR на столе или из Консьержа), даёт согласие и телефон.
2. Оставляет заявку: стол (дата, время, гости) или бизнес-ланч (блюда, время).
3. Хостес жмёт «Да» на карточке в группе персонала → гостю уходит подтверждение.
4. Гость приходит: хостес жмёт «Гость сел» (`SEATED`) или бронь закрыта в Saby Presto.

«Прошёл сценарий» — у гостя есть заявка в `table_reservation_orders` со статусом не ниже «подтверждена».
Визит (`SEATED`) считаем отдельно как сильную метрику. **[решение]**: засчитывать подтверждённую заявку или только
визит; рекомендация — подтверждённая заявка (иначе к 15.10 воронка упирается в физические визиты).

| Источник | Что даёт |
| --- | --- |
| Butler `model_interaction_audit` | каждый вызов модели: сценарий, провайдер, модель, успех, ошибка, задержка |
| Butler `telegram_messages` | сообщения гостей по дням; `/start <payload>` — источник трафика |
| Butler `saby_call_log` | вызовы Saby Presto: операция, HTTP-статус, исход, длительность |

| Concierge `analytics_events` (SQLite) | события консьержа, включая вызовы модели |

Соответствие обязательным полям:

| Поле формы | Откуда |
| --- | --- |
| псевдонимный id | `sha256(telegram_user_id + соль)`, соль не публикуется |
| дата и время | `created_at` / `received_at` / `occurred_at`, МСК |
| тип вызова | `purpose` + `scenario` (модель); `operation` (Saby); тип события (Консьерж) |
| результат | `success`, `fallback_used`; `outcome` (Saby) |
| код ошибки | `error_type`; `http_status` (Saby) |
| источник трафика | payload `/start` (deep-link сайта, QR сотрудника, Консьерж), иначе `direct` |
| LLM-cost | токены × цена GigaChat, см. [LLM_COST.md](LLM_COST.md) |

## 5. Tool calls

Один tool call = один вызов модели или инструмента, записанный в лог:
- строка `model_interaction_audit` (Butler);
- событие вызова модели в `analytics_events` (Консьерж);
- после включения агентов — строка `visit_turns` с `kind = TOOL_CALL`.

Недельное число = сумма трёх источников за пн 00:00 – вс 23:59 МСК, один SQL-запрос для формы и для еженедельного
отчёта. Число в форме и в weekly report должно совпадать — берём из одной выгрузки. Значение за неделю: **[заполнить]**.
