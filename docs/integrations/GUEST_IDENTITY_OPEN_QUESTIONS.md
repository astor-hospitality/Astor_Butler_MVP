Дата: 2026-10-11. Автор: Дима (`@dmtrshm`), разбор с двумя ИИ-ассистентами, каждое утверждение сверено с кодом `main` на `783d988`. Для Михаила, Егора и того, кто вернётся к теме.

Это не спецификация и не план к исполнению. Документ фиксирует, что выяснили, что решено, что ждёт решения и в каком порядке делать, когда решения будут. Код по теме пока не менялся.

## 1. Вопрос

Как Butler узнаёт гостя, хранится ли история по каждому гостю, как связать Telegram, MAX, веб, телефон и клиента Saby (карту лояльности), и нужна ли карточка гостя Консьержу.

## 2. Как сейчас устроено

### 2.1. Кто такой гость

| Канал | По чему узнаёт Butler | Где хранится | Попадает в `users` |
| --- | --- | --- | --- |
| Telegram | `telegram_user_id` | `users` (по `telegram_id`), `telegram_profiles`, телефон в `user_contacts` | да (`IdentityService.identifyTelegram`) |
| MAX | id чата MAX → внутренний `chat_id` из диапазона `8e12+` | `messenger_chat_bindings` (имя, username, `contact_phone`) | нет |
| Веб-чат | сессия браузера → `chat_id` из диапазона `9e12+` | `web_sessions`; телефон только в самой заявке (`guest_phone`) | нет |

Один человек в трёх каналах — три разных гостя. По телефону никто не склеивает. В `users` поле `telegram_id` обязательное и уникальное (миграция `2025-06-19-create-users.yaml`, сущность `User`), поэтому гость MAX или веба туда не помещается без миграции.

### 2.2. Какая история есть

| Что | Таблица | Ключ | Срок |
| --- | --- | --- | --- |
| Входящие сообщения Telegram: текст, телефон, `raw_payload` | `telegram_messages` | `user_id`, `chat_id` | бессрочно |
| Сообщения веб-чата | `web_messages` | сессия | 30 дней (`WebSessionRetentionJob`) |
| Согласия с версией политики | `user_consents`, `web_consents` | `user_id` / сессия | бессрочно |
| Заявки на стол и ланч | `table_reservation_orders` | `chat_id`, `telegram_user_id`, `user_id` | бессрочно |
| Предпочтения (категории `FOOD`, `DRINK`, `ALLERGY`, `SEATING`, `SERVICE`, `COMMUNICATION`, `GENERAL`) | `guest_preferences` | `chat_id`, `user_id` | бессрочно |
| Счета, журнал, оценки | `guest_bills`, `bill_operations`, `visit_reviews` | `chat_id` (в `visit_reviews` нет `user_id`) | бессрочно |
| Отзывы, чаевые, заявки Консьержа | `guest_feedback`, `tip_orders`, `concierge_requests` | `chat_id` | бессрочно |
| События аналитики | outbox → Kafka `astor.user.events` | `telegram:user:<id>` | по настройкам Kafka |
| Хронология FSM | Scylla `guest_fsm_timeline_by_guest` | гость | выключена (`ASTOR_TIMELINE_SCYLLA_ENABLED=false`) |

Карточки гостя как экрана или API нет. Хостес в карточке заявки видит 5 последних сообщений из `telegram_messages` (`TableReservationNotificationService.recentMessages`); для заявок из MAX и веба там пусто.

## 4. Saby: лояльность и клиент

Изучена документация 2026-10-11. Живым вызовом ничего не проверено: ключей нет.

| Метод | Что делает | Как определяет клиента |
| --- | --- | --- |
| `GET /retail/customer/{externalId}/bonus-balance` (Presto) | Баланс бонусов на точке | UUID клиента в Saby |
| `POST /retail/order/{externalId}/bonus-write-off` (Presto) | Списать или начислить бонусы | UUID заказа; описан для заказов на доставку |
| `GET /retail/order/list` (Saby Retail) | Продажи точки за период: сумма, позиции, оплаты, `Customer` (число), `CustomerName` | Фильтр только точка и даты; телефона и карты нет. Применимость к Presto не указана |
| `CRMClients.GetCustomerByParams` (Saby CRM) | Найти частное лицо, вернуть `UUID`, `CustomerID`, контакты | По `ContactData`; поиск именно по телефону не подтверждён |

Вывод: баланс бонусов получить можно, но для этого нужен UUID клиента в Saby, а как его узнать по телефону, документация Presto не говорит (вопрос «Как узнать идентификатор клиента?» в FAQ без ответа). Номера карты лояльности как идентификатора нет ни в одном методе. `customer.externalId` из `order/create` Butler не отправляет и обратно не получает (B4).

## 5. Предлагаемая модель

```
                      гость в Butler (users.id)
                                │
     ┌──────────────┬───────────┼──────────────┬────────────────────────┐
  Telegram id    MAX id     веб-сессия    телефон (E.164)        клиент Saby (UUID)
  при первом     при первом  на время      подтверждён, если       по подтверждённому телефону,
  сообщении      сообщении   сессии        гость прислал свой      когда Saby ответит на вопросы 1–3
                                           контакт
                                                                         │
                                                                 карта, бонусы, покупки —
                                                                 остаются в Saby
```

- Гость — это `users.id`. Новых таблиц `guests` / `guest_identities` не нужно; нужно снять обязательность `users.telegram_id` и добавить `user_id` в `messenger_chat_bindings`, `web_sessions`, `visit_reviews`.
- Склейка каналов — только по подтверждённому телефону. По имени не склеиваем. Номер, вписанный в веб-форму, даёт предположительную связь, которую подтверждает менеджер.
- Факты (заявки, предпочтения, счета, оценки) дозаполняются `user_id` по `chat_id`: диапазоны `chat_id` у каналов не пересекаются. Веб-заявки старше 30 дней — только по `guest_phone`, связь предположительная.
- Карту лояльности Butler не хранит: связь через UUID клиента Saby, данные спрашиваются у Saby.
- Предпочтения — только из явных данных (пожелания к заявкам, заметки персонала). Из переписки не извлекаем.
- Сводка для хостес в карточке заявки вместо переписки: «N заявок, последняя дата, рассадка, последняя оценка». Без трат и без аллергий до ответа юриста (см. 7).
- Ограничение модели: карточка описывает того, кто бронирует, а не того, кто ест.

## 6. Консьерж

Предложение: Консьерж не читает карточку гостя из Butler.

- Butler работает от имени ресторана (бот на юрлицо ресторана), Консьерж — от имени Astor (юрлицо Михаила). История визитов, траты и заметки персонала — данные ресторана; передача другому оператору требует отдельного согласия гостя и договора.
- Сводная история «где был, что выбирал, как оценил» по всем ресторанам естественно складывается у самого Консьержа: гость говорит с ним, он отправляет заявки.
- Из Butler в Консьерж — минимум и только по заявкам Консьержа: статус, состоялся ли визит, оценка. Траты, телефон, заметки персонала, визиты мимо Консьержа — нет.
- Сейчас в `data/venues.json` Консьержа один ресторан (AERIS), сводка по ресторанам преждевременна. Решить нужно принцип.
