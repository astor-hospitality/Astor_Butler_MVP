# Агенты на API Sber500 × Disrupt: проверка, нагрузка, стоимость

Дата замеров: 2026-10-15. Объект: агенты переговоров Батлера (`AgentLoop`) и Консьержа на OpenAI-совместимом API
программы (`https://shared1.multitool.works:4000/v1`, прокси LiteLLM 1.100.4, модели у Cloud.ru Evolution Foundation Models).
Выкладка и откат — `SBER500_LLM_ROLLOUT.md`. Числа Консьержа подробно — его `docs/operations/SBER500_LLM_ACCEPTANCE.md`.

Обозначения: **И** — измерено; **О** — оценка по измеренным величинам с явной предпосылкой. Зелёный CI и нагрузка на заглушке
не подтверждают работу гостевого сценария: это подтверждает только проверка в чате Михаила после выкладки.

## 1. Контракт API (И, синтетика)

| Проверка | Результат |
| --- | --- |
| `GET /models` | 200, 101 модель (имена — свои: `gigachat-3-pro`, `gpt-4o-mini`, …) |
| `GET /model/info`, `/key/info` (документированные эндпоинты LiteLLM) | 200: цены за токен по моделям; бюджет ключа `max_budget 75000`, лимитов RPM/TPM у ключа нет (`null`) |
| Генерация | 8 из 9 моделей ответили; `gpt-5-mini` — 400: принимает только `temperature=1` |
| Полный цикл инструментов: запрос → `tool_calls` → результат `tool` → ответ | `gigachat-3-pro` 14/15 циклов (1 — HTTP 500 апстрима), `gpt-4o-mini` 10/10, `gpt-4.1-mini`, `claude-haiku-4.5`, `deepseek-v4-flash`, `qwen3-235b-a22b`, `gigachat3.5-432b-a28b` — по 1/1 |
| **`gigachat-2-max`** | **инструменты не вызывает**: пишет вызов текстом, хотя `/model/info` заявляет `supports_function_calling=true` |
| Аргументы | строкой JSON, разбираются в объект во всех успешных вызовах; `id` вызова есть (`chatcmpl…`, `call_…`, `toolu_…`) |
| `parallel_tool_calls=false` | принимают `gigachat-3-pro` и `gpt-4o-mini` |
| `usage` | есть всегда; у `gigachat-3-pro` к входу добавляется ~1 200 скрытых токенов апстрима (1 223 на вопрос из 20 токенов) |

| Цена | `x-litellm-response-cost` в каждом ответе = токены × цена `/model/info` (сверено вручную); сумма заголовков ≈ 4.99 ₽ против прироста `spend` ключа 5.02 ₽ за то же окно (расхождение 0.6% — пара ранних вызовов без сохранённого заголовка) |

## 2. Выбор модели

Живые прогоны на боевых промптах и всех 13 схемах инструментов Батлера (И, синтетические факты, броней нет):

| | gigachat-3-pro | gpt-4o-mini |
| --- | --- | --- |
| Инструменты | работают | работают |
| Ход Батлера: время | 1.0–2.6 с | 2.7–3.9 с |
| Ход Батлера: стоимость | 0.345 ₽ (8.2 тыс. токенов на входе) | 0.072 ₽ (4.2 тыс.) |
| Сообщение Консьержа: время / стоимость | 1.7–2.4 с / 0.214 ₽ | 3.3–7.6 с / 0.148 ₽ |
| Хвост задержки | тяжёлый (p95 шага 8.9 с) | ровный |
| Заявка до «да» гостя на «Есть стол?», прежний промпт | **5 из 5** | 1 из 5 |
| То же с правилом в промпте (этот PR) | 0 из 5 | 0 из 5 |
| Где обрабатываются данные | модель Сбера через Cloud.ru | модель OpenAI через шлюз Cloud.ru: место обработки из API не проверить |

**Решение Михаила 15.10: `gigachat-3-pro` для обоих агентов.** Ниже — как к нему пришли.

Где модель работает — по тарифу Cloud.ru (приложение 7.EVO.11.2, версия 260915): «партнёрская модель» — у внешнего
провайдера, без пометки — в инфраструктуре Cloud.ru. GPT-4o-mini, Claude, DeepSeek V4 Flash, GLM-4.6 — партнёрские;
GigaChat 3 Pro, GigaChat-2-Max, GigaChat3-10B, gpt-oss-120b, Qwen3.5/3.6 — в Cloud.ru. Цены прокси совпадают с этим тарифом
до копейки: рубли с НДС 22%.

Второй раунд, российские модели дешевле `gigachat-3-pro`, те же боевые промпты (И):

| | gpt-oss-120b | gigachat3-10b-a1.8b |
| --- | --- | --- |
| Батлер: заявка до «да» на «Есть стол?» | 0 из 5 | 0 из 5 |
| Батлер: заявка после «да» | да | **нет** — после «Оформляем» не вызвал `reservation_create` |
| Ход Батлера | 0.068 ₽, 1.3–4.3 с | 0.024 ₽, 0.4–2.3 с |
| Сообщение Консьержа | 0.098 ₽; **1 из 3 — ошибка модели** (fallback после ответа ресторана) | 0.026 ₽, без сбоев |

`gigachat3-10b` не выполняет задачу; `gpt-oss-120b` у Батлера работает и в 5 раз дешевле, но данных мало и у Консьержа был
сбой — кандидат на удешевление Батлера после пилота (цикл гостя 1.33 → ~0.78 ₽), отдельной проверкой на большем числе диалогов.

Исходная рекомендация для пилота — `gigachat-3-pro`: инструменты подтверждены, задержка на боевых промптах ниже,
цена подтверждена, данные гостей остаются у российского провайдера. Риск — хвост задержки: часть ходов уйдёт в fallback
(на стенде 2–5%, §3). По трём критериям задачи (инструменты, задержка, цена) сильнее **`gpt-4o-mini`**: ровная задержка и
в 2.3 раза дешевле цикл гостя, — но это иностранная модель, и передача ей текста гостей требует решения Михаила (152-ФЗ).
Переключение между ними — одна переменная (`ASTOR_AGENT_MODEL`, `AGENT_MODEL`).

Правило в промпте Батлера («перед `reservation_create` дождись от гостя «да»; на «есть ли стол?» — только
`table_availability`») добавлено отдельным коммитом: без него требование «подтверждение гостем заказа» на новых моделях не
выполняется. На GigaChat-2-Pro (текущий прод, путь отката) правило в живую не проверялось.

## 3. Нагрузка (И, заглушка модели)

Условия: MacBook (Apple Silicon, 8 ядер), Java 25, Node 26 (CI Консьержа — Node 22); генератор и сервис в одном процессе;
открытая модель нагрузки (поступления не ждут ответов); ступени по 30 с: 1 → 2 → 5 → 10 RPS, стресс 20 и 40 RPS.
Задержка заглушки модели — по профилям живых замеров (§1): `gigachat-3-pro` (лог-нормальное, медиана 1.16 с, p95 8.9 с),
`gpt-4o-mini` (медиана 1.62 с, p95 1.97 с), `fast` (50 мс — собственные накладные расходы).

Не входят: HTTP-контроллер Батлера, PostgreSQL (идемпотентность — на H2), Telegram, сеть до API. ВМ Cloud.ru — 4 vCPU,
общая с Vedal: на ней цифры CPU будут выше.

**Единицы.** RPS — запросов к сервису в секунду: у Батлера переговорный ход (`ButlerAgent.negotiate`, то, что выполняет
`POST /api/negotiation/v1/turn`), у Консьержа сообщение гостя агенту. «Вызовов модели/с» — запросов к API модели в секунду.
TPM — токенов (вход + выход) в минуту к API модели; TPS — то же в секунду; «выход TPS» — только сгенерированные токены.

- До 40 RPS на сервис ошибок нет, повторных броней нет (у Батлера-заглушки уникальных ходов столько же, сколько вызовов),
  собственные накладные расходы — десятки миллисекунд на ход. Узкое место — задержка и лимиты модели, не сервисы.
- На профиле `gigachat-3-pro` хвост модели упирается в таймауты (`OPENAI_COMPATIBLE_TIMEOUT_MS` 15 с, вызов 20 с, ход 25 с):
  5% ходов Батлера и 3–4% сообщений Консьержа уходят в fallback; гость получает прежний сценарный ответ.
- 10 RPS живьём — это 4–5 млн TPM и 2.6–12.4 тыс. ₽ в час на сервис (§4); поэтому основной прогон — на заглушке, а живые
  вызовы — ограниченная проверка (§2: 3 хода/сообщения на модель плюс 5 первых ходов).

Повторить:

```bash
mvn -o test -Dtest=AgentNegotiationLoadTest -Dastor.load=true -Dastor.load.profile=gigachat-3-pro -Dsurefire.failIfNoSpecifiedTests=false
```

```bash
OPENAI_COMPATIBLE_BASE_URL=... OPENAI_COMPATIBLE_API_KEY=... mvn -o test -Dtest=AgentNegotiationLiveTest -Dastor.live=true -Dastor.live.model=gigachat-3-pro -Dsurefire.failIfNoSpecifiedTests=false
```

У Консьержа — `npm run load:agent -- --profile gigachat-3-pro` и `npm run live:agent -- --model gigachat-3-pro`.
Живая проверка стоит около 1–2 ₽ за прогон; ключ берётся из окружения и не печатается. На macOS без нативного DNS Netty живой
тест Батлера идёт через `HttpURLConnection` (Reactor Netty уходит в публичный DNS по IPv6); на Linux-ВМ это не нужно.

## 4. Стоимость и DAU

Цикл гостя (О): бронь через агента = 3 сообщения Консьержу, из них 2 доходят до Батлера (так было в живых прогонах).
Стоимость — по заголовкам прокси (И), с учётом кэширования промптов, поэтому ниже, чем «токены × прайс».

| | gigachat-3-pro | gpt-4o-mini |
| --- | ---: | ---: |
| Сообщение Консьержа (И) | 0.214 ₽, 7.3 тыс. / 104 токена, 2.3 вызова | 0.148 ₽, 6.5 тыс. / 154, 3 вызова |
| Ход Батлера (И, с правилом согласия) | 0.345 ₽, 8.2 тыс. / 56, 2 вызова | 0.072 ₽, 4.2 тыс. / 53, 2 вызова |
| **Цикл гостя** = 3 × сообщение + 2 × ход (О) | **1.33 ₽**, 38 тыс. токенов, 11 вызовов | **0.59 ₽**, 28 тыс. токенов, 13 вызовов |

LLM cost/DAU = цикл × взаимодействий на DAU (О). DAU — как в `SCOREBOARD.md` Консьержа: пользователь с полезным действием за
день. Фактических DAU и частоты взаимодействий у агента пока нет (агент закрыт allowlist), поэтому два сценария:
1 цикл на DAU в день и 1.5 (вопросы после брони).

| DAU | gigachat-3-pro, ₽/день (1 / 1.5 цикла) | ₽/мес | gpt-4o-mini, ₽/день | ₽/мес | Бюджет 75 000 ₽ хватит (gigachat, 1 цикл) |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 50 | 67 / 100 | 2 000 / 3 000 | 29 / 44 | 880 / 1 320 | ~3 года |
| 300 | 400 / 600 | 12 000 / 18 000 | 176 / 264 | 5 300 / 7 900 | ~6 месяцев |
| 1 000 | 1 333 / 2 000 | 40 000 / 60 000 | 586 / 880 | 17 600 / 26 400 | ~56 дней |

Нагрузка от DAU (О): 5 запросов к сервисам на цикл, 20% дневного трафика в пиковый час: 1 000 DAU ≈ 0.28 RPS на оба
сервиса; 10 RPS на сервис соответствуют ~36 000 DAU при таком профиле.

Требование к API на 10 RPS одного сервиса (О, токены из живых прогонов):

| | Модель | Вызовов/с | TPM (вход+выход) | TPS | Выход TPS | ₽ в час |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Консьерж | gigachat-3-pro | 23 | 4.46 млн | 74 400 | 1 040 | 7 700 |
| Батлер | gigachat-3-pro | 20 | 4.96 млн | 82 700 | 560 | 12 400 |
| Консьерж | gpt-4o-mini | 30 | 4.02 млн | 67 000 | 1 540 | 5 300 |
| Батлер | gpt-4o-mini | 20 | 2.55 млн | 42 400 | 530 | 2 600 |

### План бюджета (О)

Ключ общий у Батлера и Консьержа: 75 000 ₽, лимитов RPM/TPM/бюджета по моделям у ключа нет, выпускать свои ключи с лимитами
мы не можем. На все проверки 15.10 ушло 14.67 ₽.

| Статья | На `gigachat-3-pro` |
| --- | ---: |
| Пилот в чате Михаила, ~50 циклов гостя | ~70 ₽ |
| Приёмка и демонстрация конкурса, живые проверки | до 500 ₽ |
| Открытие гостям AERIS, 50–300 DAU | 2 000–12 000 ₽ в месяц |
| Запас на ошибки и повторные прогоны | остаток |

Главный риск — не расход по плану, а сбой: зацикленный агент на 10 RPS тратит 7.7–12.4 тыс. ₽ в час, весь ключ — за ~4 часа.
Поэтому у каждого агента дневной лимит: `ASTOR_AGENT_DAILY_BUDGET_RUB` (Батлер) и `AGENT_DAILY_BUDGET_RUB` (Консьерж), пилот —
по 100 ₽ за день заведения (~150 циклов, с запасом на порядок). Расход считается по цене, которую назвал сервис
(`x-litellm-response-cost`), у Батлера без неё — по тарифу call log; модель без цены не считается. Лимит исчерпан — агент до
следующего дня не вызывает модель, гости получают прежние сценарии (не другую модель); WARN при 80% и 100%; счёт в памяти,
перезапуск начинает день заново. Остаток ключа — раз в день по `/key/info` (`SBER500_LLM_ROLLOUT.md`, §10). При открытии
гостям лимит пересчитывается: DAU × циклы × 1.33 ₽ × 2 (запас), но не больше 1/30 остатка в день.

## 5. Наблюдаемость

Батлер (`/actuator/prometheus`): `astor_agent_model_calls_seconds{provider,model,outcome,quantile}` (p50/p95/p99, число и
ошибки по `outcome=answer|tool_call|error|timeout`), `astor_agent_model_tokens_total{direction}`,
`astor_agent_turns_total{outcome,reason}` (fallback по причине, в том числе `daily_budget`), `astor_agent_tool_calls_total{tool,outcome}`,
`astor_agent_budget_spent_rub` и `astor_agent_budget_limit_rub` (расход за день заведения и лимит). Построчно —
call log (`CALL_LOG.md`: модель, токены, задержка, стоимость) и `model_interaction_audit` (без аргументов инструментов,
без текстов при отсутствии согласия).

Стоимость в call log: `ModelTariff` знает `GigaChat-3-Pro` (73/176 ₽, совпадает с ценой прокси); у `gpt-4o-mini` тарифа нет —
стоимость пустая, не ноль. Подтверждённые цены прокси добавляются так: `ASTOR_CALL_LOG_TARIFFS="gpt-4o-mini=29.463,117.852"`.
Call log считает по прайсу без скидки за кэш — это верхняя граница; фактическое списание — `x-litellm-response-cost` и
`spend` ключа (`GET /key/info`).

## 6. Чего нет и что не проверено

- Лимиты апстрима RPM/TPM для `gigachat-3-pro` не отдаются (заголовков нет), у ключа лимитов нет; при 4–5 млн TPM нужен ответ
  организаторов.
- Валюта цен в API не указана (вывод «рубли» — по совпадению с прайсом GigaChat).
- 429 живьём не воспроизведён; обработка — только на заглушке.
- Нагрузка не на ВМ и без PostgreSQL, HTTP-контроллера и Telegram.
- Реальные DAU и частота взаимодействий агента — нет данных; стоимость на DAU — сценарии.
- Правило согласия на GigaChat-2-Pro (путь отката) живьём не проверено.
- Где обрабатываются данные для не-сберовских моделей — из API не проверить.
- Гостевой сценарий подтверждается только проверкой в чате Михаила после выкладки (`SBER500_LLM_ROLLOUT.md`, §6).
