# График смен из фото — кто на смене (2026-10-16)

Персонал AERIS публикует фото или скрин графика в тему «График» группы персонала. Butler распознаёт картинку
vision-моделью, сопоставляет имена со справочником `astor_staff_members`, переспрашивает неуверенное, и после «Верно»
отвечает другим сервисам и команде `/смена`, кто на смене сейчас по роли.

Выключено по умолчанию: `astor.staff.schedule.enabled=false` (`ASTOR_STAFF_SCHEDULE_ENABLED`). Без флага бот
не трогает тему, `/смена` неизвестна, `StaffRoster` отвечает «никого» — поручения и карточки идут как раньше.

## Поток

```
фото/скрин в тему «График» (chat -1002768239841, thread 4)
  └─ бот скачивает самую крупную версию (≤ 8 МБ), отдельным потоком — апдейты Telegram не ждут модель
      └─ ModelGateway.analyzeImage (vision-модель провайдера: CLOUDRU_VISION_MODEL / GIGACHAT_VISION_MODEL …)
          └─ JSON: дни → имя, роль, часы
              └─ разбор (StaffScheduleParser) → сопоставление (StaffNameMatcher) → staff_shift_schedules/entries
                  ├─ есть неуверенные имена → одно сообщение «Уточните, кто это» с кнопками → CLARIFYING
                  └─ всё ясно → «На сегодня: хостес …, менеджер …, официанты …» [Верно] [Исправить] → PROPOSED
[Верно]    → CONFIRMED: этот график отвечает за свои даты; сообщение теряет кнопки, внизу «✅ Верно — Маша (@masha)»
[Исправить] → REJECTED: в силе остаётся прежний подтверждённый график; бот просит прислать фото ещё раз
```

Все ответы бота уходят в ту же тему (`message_thread_id`), кнопки уточнения и подтверждения — в том же одном
сообщении: после выбора последнего имени оно превращается в подтверждение.

## Формат ответа модели

Промпт просит строго JSON, без пояснений. Сегодняшняя дата и день недели передаются в промпте, чтобы модель
превратила «Пн/Вт» и «16.10» в даты.

```json
{"days": [{"date": "2026-10-16", "staff": [
  {"name": "Анна С.", "role": "хостес", "hours": "10:00-22:00"}
]}], "unreadable": 1}
```

Разбор терпим к тому, что модели делают на практике:

| Что пришло | Как читаем |
|---|---|
| ```` ```json … ``` ````, текст до/после JSON | берём объект от первой `{` до последней `}` |
| `"date"`: `2026-10-16`, `16.10`, `16.10.2026`, `16/10` | год без указания — ближайший к сегодняшней дате |
| `"hours"`: `10-22`, `10:00–22:00`, `с 10 до 22`, `10.00-23.00` | начало/конец; конец ≤ начала — смена через полночь |
| `"hours"`: `В`, `вых`, `выходной`, `отпуск`, `-` | строка пропускается: человек не на смене |
| `"hours"`: пусто, `до закрытия`, нечитаемо, голое `11` (это длина смены, а не начало) | часы неизвестны: человек на смене весь этот день |
| `"hours"`: `с 12`, `12:00` | известно только начало: на смене с этого часа до конца дня |
| `"role"`: официант/waiter, хостес/hostess/администратор зала, менеджер/управляющий/администратор/старший смены | WAITER / HOSTESS / MANAGER |
| роль пустая | роль из справочника, если имя нашлось однозначно |
| бармен, повар, кухня и прочие роли | пропускаются: справочник знает только официантов, хостес и менеджеров |

Ограничения: дни в окне `[сегодня − 7; сегодня + 45]` (неделя с понедельника, выложенная в среду, целиком), не больше 31 дня и 400 строк, имя ≤ 60 символов. Ответ без
единой пригодной строки — «Не смог прочитать график», в базе ничего не появляется.

## Ошибки распознавания

| Ситуация | Поведение |
|---|---|
| Vision-модель не настроена / недоступна / пустой ответ | «Не получилось распознать график: модель недоступна. Пришлите позже или напишите менеджеру.» Ничего не сохраняется. |
| Ответ не JSON, пустые дни | «Не смог прочитать график. Пришлите фото ровнее и крупнее (или скрин таблицы).» |
| Модель сообщила `unreadable > 0` | в подтверждении строка «Не разобрал строк: N — проверьте фото» |
| Имя совпало однозначно (точно, по staff_id или по запомненной форме) | MATCHED, без вопросов |
| Совпало несколько человек, или только «похоже» (уменьшительное, опечатка OCR в одну букву, падеж) | AMBIGUOUS: строка с кнопками-кандидатами (до 3) и «Никто из них»; не угадываем |
| Никто не похож | UNKNOWN: в подтверждении «Нет в справочнике: Пётр (официант)» — такой строке поручения не адресуются |
| Выбор кнопкой | все дни этого имени в графике получают выбранного сотрудника; форма имени запоминается (`staff_name_aliases`) — в следующий раз без вопроса |
| Одно и то же фото пришло дважды (повтор апдейта) | уникальный ключ (чат, сообщение) — второй раз не распознаём |
| Альбом из нескольких фото | каждое фото — отдельный график; позже подтверждённый перекрывает свои даты |
| Ошибка разметки модели (не тот человек) | «Исправить» → график не действует; переснять фото. Подтверждённый можно перекрыть новым фото |

«Неуверенно» значит: кандидат найден не точным совпадением всех слов имени. Падеж («Анне»), уменьшительное («Аня»),
одна буква OCR («Анма») и общий префикс — только кандидаты, не ответ. Имя, точно подходящее двоим, — тоже вопрос.

## Кто на смене

Для дня D действует **последний подтверждённый** график, чьи даты покрывают D (даже если в нём на D пусто —
значит, график так сказал). Неподтверждённые и отклонённые графики не действуют.

`StaffRoster` (Spring-бин, `domain.roster`) — для поручений и карточек:

- `onShiftNow(role)` — сотрудники роли, у кого сейчас (часовой пояс заведения, `Asia/Yekaterinburg`) идёт смена:
  сегодняшние строки с `начало ≤ сейчас < конец`, вчерашние через полночь, и строки без часов на сегодня;
- `onShift(date)` — все подтверждённые строки дня;
- в ответ попадают только MATCHED-строки активных сотрудников справочника (`staff_id`, имя, роль, часы).

`/смена` (`/shift`) в любой теме группы персонала, ответ — в ту же тему:

```
Сейчас на смене (16.10, 14:00):
хостес — Алиса Тестова (до 22:00)
менеджер — Борис Примеров (до 23:00)
официанты — Вера Образцова (до 22:00), Глеб Макетов (до 00:00), Егор
```

`/смена завтра`, `/смена 17.10`, `/смена пт` — весь день с часами. Если более новый график на этот день ждёт «Верно»,
бот напоминает об этом.

Подключение `StaffRoster` к адресатам поручений (StaffAssignees) и к упоминаниям в карточках хостес — отдельным PR:
здесь только источник ответа.

## Приватность

- Сохраняем минимум: дата, имя как в графике (≤ 60 символов), роль, часы, `staff_id` после сопоставления; кто
  прислал фото и кто нажал кнопку — «имя (@username)». Телефонов нет: промпт запрещает их выводить, разбор вырезает
  из имени телефон целиком и вообще любые цифры, а строки, где не остаётся ни одной буквы, пропускаются.
- Картинку не храним и не архивируем (ни на диске, ни в S3): байты живут в памяти до ответа модели.
- Сырой ответ модели не сохраняем и не логируем; в логе только счётчики (дней, строк, неуверенных) и модель.
- В чат бот пишет только имена из справочника и имена с картинки, которую персонал сам опубликовал в этом чате.
- Удаление: `active=false` у сотрудника убирает его из ответов `StaffRoster` сразу; `ON DELETE CASCADE` чистит
  запомненные формы имени при удалении из справочника.

## Telegram

- Бот должен видеть все сообщения группы (админ или privacy mode выключен) — так уже работает чат хостес.
- Тема распознаётся по `message_thread_id`; фото в других темах и в других чатах бот не трогает.
- Кнопки нажимает любой участник группы; в базе остаётся, кто подтвердил (`имя (@username)`).

## Настройки

| Свойство | Env | По умолчанию |
|---|---|---|
| `astor.staff.schedule.enabled` | `ASTOR_STAFF_SCHEDULE_ENABLED` | `false` |
| `astor.staff.schedule.chat-id` | `ASTOR_STAFF_SCHEDULE_CHAT_ID` | `-1002768239841` |
| `astor.staff.schedule.thread-id` | `ASTOR_STAFF_SCHEDULE_THREAD_ID` | `4` |
| `astor.staff.schedule.tenant` | — | `AERIS` |
| `astor.staff.schedule.timezone` | — | `Asia/Yekaterinburg` |
| `astor.staff.schedule.max-tokens` | `ASTOR_STAFF_SCHEDULE_MAX_TOKENS` | `2048` |

Ответ модели длиннее обычного (неделя × 8 человек ≈ 1–2 тыс. токенов), поэтому `ModelVisionRequest` получил
необязательный `maxTokens`; его учитывают OpenAI-совместимые шлюзы (Cloud.ru) и GigaChat, остальные — как раньше.

## Код и тесты

| Где | Что |
|---|---|
| `domain/roster/StaffScheduleParser` | промпт и разбор ответа модели |
| `domain/roster/StaffNameMatcher` | сопоставление имени со справочником: MATCHED / AMBIGUOUS / UNKNOWN |
| `domain/roster/StaffScheduleService` | распознать → сопоставить → сохранить; кнопки; `/смена` |
| `domain/roster/StaffRoster` | «кто на смене» для других сервисов |
| `domain/roster/StaffScheduleTelegram` | тема, скачивание картинки, ответы и правки сообщений в Telegram |
| `src/test/resources/roster/` | синтетическая картинка графика и записанный ответ модели на неё — имена вымышлены |

Тесты: `StaffScheduleParserTest` (разбор ответа, форматы часов и дат, телефоны), `StaffNameMatcherTest`
(сопоставление), `StaffScheduleServiceTest` (весь путь на реальных миграциях в H2: вопрос, кнопки, «Верно/Исправить»,
кто на смене, `/смена`, повтор фото, недоступная модель), `StaffScheduleTelegramTest` (тема, ответ в тему, правка
сообщения кнопкой). Живой прогон на настоящей vision-модели не делался (платный API): первым делом при включении —
тестовая картинка из фикстур в тему.

## Выкладка

Миграция `2026-10-16-staff-shift-schedule` только добавляет таблицы. Включение — `ASTOR_STAFF_SCHEDULE_ENABLED=true`
после выкладки, проверка: фото тестового графика с вымышленными именами в тему → подтверждение → `/смена`.
Мерж и выкладка — Codex, не в окно бизнес-ланча 12:00–16:00 Екб.
