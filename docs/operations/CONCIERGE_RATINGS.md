# Astor Concierge: рейтинги заведений — источники, ограничения, запуск

Дата: 2026-10-05. Автор: Рома (`0xLaki`). Задача: [#21](https://github.com/astor-hospitality/Astor_Butler_MVP/issues/21).

## Коротко

- Автоматически получать и хранить рейтинги Яндекс Карт и 2ГИС по их публичным условиям нельзя. Парсер не написан намеренно, см. раздел «Что говорят источники».
- Остальное из задачи сделано: хранение рейтинга каждого источника со ссылкой, идентификатором объекта и временем проверки, статус свежести, защита от параллельных запусков, атомарная публикация, откат, лента с настоящей датой проверки.
- Сейчас цифры вносит человек одной командой. Автоматический источник подключается настройками сервера без изменения кода и ленты, когда появится разрешение правообладателя.

Хранить снимок, усреднять и сортировать по сохранённому нельзя без отдельного условия в договоре |

Чего проверить не удалось: документация `docs.2gis.com` и сам `catalog.api.2gis.com` с рабочего компьютера не открылись, ключа и договора нет, живого вызова API не было. Поэтому путь к полю рейтинга в примере настроек ниже взят из описания формата и помечен как непроверенный.

Отдельно и честно: под те же пункты формально подпадает и ручной перенос цифр на наш сайт, который уже есть в ленте. Он не автоматический, но это публикация данных сервисов в коммерческом продукте. Чистый путь здесь один: разрешение правообладателя. Решение за Михаилом.

## Разрешённые варианты

| Вариант | Что даёт | Чего не даёт |
| --- | --- | --- |
| 1. Оператор проверяет страницы и вносит цифры командой | Работает сегодня, всё остальное уже автоматическое | Не автоматическое получение; оговорка из предыдущего абзаца остаётся |
| 2. Разрешение от источника | 2ГИС: счёт-оферта с прямым правом хранить рейтинг заданное время. Яндекс: письменное разрешение по п. 4.6. После этого источник включается настройками | Срок и цена неизвестны, нужен запрос от компании |
| 3. Данные от заведений-партнёров | У владельца заведения есть доступ к своим кабинетам на обеих картах. Пункт в договоре подключения к Astor закрывает вопрос для подключённых заведений | Не покрывает заведения без договора |
| 4. Только официальные виджеты, без хранения | Законно без переговоров | Нет среднего и сортировки по нему, то есть нет самой ленты «по рейтингу» |
| 5. Собственная оценка Astor по отзывам гостей после брони | Не зависит от чужих условий | Нужны гости и время |

Предложение: вариант 1 сейчас, запросы по вариантам 2 и 3 параллельно.

## Как устроено

```text
frontend/astor-butler/
├── data/venues.json                # заведения и ссылки на объекты карт; рейтингов здесь больше нет
├── data/ratings/snapshot.json      # опубликованный снимок рейтингов
├── js/feed-ratings.js              # правила показа и сортировки, без DOM и сети
└── js/feed.js                      # лента
scripts/concierge_ratings/          # обновление снимка, Node 22+, без зависимостей
├── update.mjs                      # команды record, run, status, rollback
├── lib/                            # правила снимка, файлы, запросы, источники
└── test/                           # 24 теста
```

Скрипт лежит вне каталога сайта: сайт целиком копируется в веб-сервер, и инструменту там делать нечего.

Правила:

- Рейтинг привязан к идентификатору объекта в ссылке на карту, а не к названию. Сменился идентификатор — прежняя цифра не переносится.
- Неудачная проверка не меняет сохранённый рейтинг. Последнее удачное значение остаётся, рядом записывается время и код сбоя. Ноль, пустое значение и число вне диапазона от 1 до 5 рейтингом не считаются.
- Свежесть: проверено не более `staleAfterHours` часов назад (по умолчанию 168). Лента считает устаревание сама на момент просмотра, поэтому снимок, который перестали обновлять, тоже покажется устаревшим.
- Среднее считается только по действительным значениям. Устаревшее значение участвует и помечается.
- AERIS остаётся отдельным блоком «Выбор Astor» при любом рейтинге и в сортировке не участвует.
- Публикация: проверка снимка, копия текущего файла в `snapshot.prev.json`, запись во временный файл и замена одним переименованием. Читатель видит либо старый файл, либо новый.
- Одновременно работает один запуск. Замок старше 15 минут считается брошенным.
- Повреждённый опубликованный файл не перезаписывается: команда завершается с ошибкой и предлагает откат.

### Формат снимка

Это договорённость с лентой ([#22](https://github.com/astor-hospitality/Astor_Butler_MVP/issues/22)). Менять только вместе с `schema`.

```json
{
  "schema": 1,
  "generatedAt": "2026-10-04T12:14:00.000Z",
  "staleAfterHours": 168,
  "venues": {
    "aeris": {
      "yandex": {
        "sourceId": "103837967593",
        "url": "https://yandex.ru/maps/org/aeris/103837967593/",
        "rating": 4.8,
        "provider": "manual",
        "checkedAt": "2026-10-04T12:14:00.000Z",
        "updatedAt": "2026-10-04T12:14:00.000Z",
        "status": "fresh",
        "lastFailure": null
      }
    }
  }
}
```

`checkedAt` — последняя удачная проверка. `updatedAt` — когда значение последний раз изменилось. `status` (`fresh`, `stale`, `missing`) верен на момент `generatedAt`. `lastFailure` — `{at, code}` последней неудачной попытки после удачной. `rating` равен `null`, пока источник ни разу не ответил.

Первый снимок перенесён из `venues.json`: это ручная проверка 2026-10-04, время взято из коммита, которым цифры были внесены.

## Запуск

Из корня репозитория:

```bash
# человек открыл страницы карт и вносит то, что на них написано
node scripts/concierge_ratings/update.mjs record aeris:yandex=4.8,gis=4.8 momo:yandex=4.9,gis=4.9

# что сохранено и что пора проверить
node scripts/concierge_ratings/update.mjs status

# запуск по расписанию: читает разрешённые источники, обновляет статусы
node scripts/concierge_ratings/update.mjs run

# вернуть предыдущий снимок
node scripts/concierge_ratings/update.mjs rollback
```

Параметры: `--out <каталог>` (по умолчанию `frontend/astor-butler/data/ratings`), `--venues <файл>`, `--stale-after-hours <N>`, `--dry-run`.

Код завершения: `0` всё свежее; `2` есть устаревшие, непроверенные или неудачные; `3` идёт другой запуск; `1` команда не выполнена. Команда `record` требует ввести каждое значение: отметить «проверено» без цифры нельзя.

Расписание на сервере, пример для cron. Ставит оператор сервера, в этом PR расписание нигде не включено:

```cron
# каждый день в 09:00: обновить статусы и разрешённые источники; ненулевой код — повод посмотреть
0 9 * * * cd /opt/astor/repo && node scripts/concierge_ratings/update.mjs run --out /opt/astor/ratings >> /var/log/astor-ratings.log 2>&1
```

### Автоматический источник

Включается только переменными окружения сервера. Ключ в репозиторий, в лог и в сообщения об ошибках не попадает.

```text
ASTOR_RATINGS_GIS_URL=https://<адрес API>?id={id}&key={key}
ASTOR_RATINGS_GIS_KEY=<ключ>
ASTOR_RATINGS_GIS_RATING_PATH=result.items.0.reviews.general_rating   # не проверено живым вызовом
ASTOR_RATINGS_GIS_LICENSE=storage-permitted
```

Для Яндекса те же имена с `YANDEX`. Без `…_LICENSE=storage-permitted` запуск завершается ошибкой: это подтверждение оператора, что договор разрешает хранить данные. Запросы идут по одному, с паузой не меньше секунды, таймаутом 8 секунд и двумя повторами с растущей паузой; `Retry-After` источника соблюдается; переадресации не выполняются; только HTTPS.

### Как снимок попадает в боевую ленту

Сейчас сайт целиком копируется в образ (`docker/glasses/frontend.Dockerfile`), поэтому новый снимок попадает к гостям вместе с релизом: записать цифры, закоммитить `snapshot.json`, выпустить релиз обычным порядком.

Чтобы обновлять без релиза, каталог со снимком нужно подключить в контейнер сайта только для чтения. Подключать именно каталог: при подключении одного файла замена переименованием в контейнере не видна.

```yaml
# предложение, в этом PR не применено
volumes:
  - /opt/astor/ratings:/usr/share/nginx/html/data/ratings:ro
```

Это изменение развёртывания, его согласует и делает Михаил.

### Откат

- Данные: `node scripts/concierge_ratings/update.mjs rollback` возвращает предыдущий снимок.
- Код: откат PR возвращает ленту к рейтингам внутри `venues.json`.

## Что не сделано

- Автоматическое получение рейтингов: нет разрешённого источника.
- Живая проверка автоматического источника: нет ключа и договора. Проверено на ответах, написанных вручную, см. `scripts/concierge_ratings/test/fixtures/README.md`.
- Расписание на сервере и подключение каталога в контейнер: нет доступа и это вне моей зоны. Выше примеры.
- Подпись «2ГИС» со ссылкой в ленте: обязательна только при работе через их API.
